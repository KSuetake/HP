## 💡 コアフィロソフィー (Core Philosophy)

本ドキュメントは、一般的なWebノウハウの上位に位置づけられる、**STK Labにおける最上級の執筆規範・思考フレームワークであり、エディトリアル規約の単一正本（Single Source of Truth: SSOT）**である。
AIおよび執筆者は、記事の企画・構成・執筆・推敲・レビューの全フェーズにおいて、常に本規範を最優先で適用する。スキル定義（`SKILL.md`）や運用ガイド（`articles/README.md`）等にルール詳細を重複定義せず、あらゆる執筆規約の改定・集約は本ドキュメントにおいて行う。

単に情報を並べるのではなく、**「読者が迷わず、心地よく理解でき、生活にゆとりを取り戻せるか」**を究極の目的として文章を紡ぐ。

## 🏛️ 普遍的原則 (Universal Principles)

### 階層構造と「3部品構成」の原則 (The Rule of Three Components)

- **原則**: アウトラインは論理的な階層構造（H2 → H3 → 箇条書き/H4）で組み立て、**中間〜下位の各階層（H3・H4・箇条書き等）は可能な限り「3つの部品（3要素）」で構成する**。
- **トップレベル（H2）の扱い**:
  - トップレベル（記事全体の大見出し・章立て）は、テーマの全体像や読者の導線に応じて章数が決まるため、**3つにこだわる必要はない**（例：リード → 基礎・判断基準 → 実践ステップ1〜N → FAQ → まとめ 等）。
  - 「3部品構成」が最も強く機能するのは、各セクション（H2）の内部を展開する中見出し（H3）や、各節内の小見出し（H4）・箇条書きの階層である。
- **意図と効能**:
  - 人間の脳が最も記憶・処理しやすく、安心感とリズムを覚える黄金数が「3」。
  - 2要素だと比較や対立に偏りやすく、4要素以上だと情報過多で流し読みしにくくなる。3要素に整理することで論点の本質が凝縮される。
- **階層ごとの適用例**:
  - H2（メイン章）: テーマに応じた自然な章立て（導入 → 基礎 → 実践ステップ → FAQ → まとめ）
  - H3（各章の内部展開）: ①選定（何を買うか） / ②調達・タイミング（いつ買うか） / ③出口（どう手放すか）
  - H4 / 箇条書き（詳細展開）: 各節の中身も3つの具体例や3つのステップで整理する。
- **リスト記法の厳密な意味づけ（記法自体の構造化）**:
  - **順序付きリスト（1. 2. 3.）**: 手順、ステップ、時系列の進行など、順番に意味があるもののみに使用する。「Step 1」等の冗長なラベルは不要で、ナンバリング自体で構造を語る。
  - **箇条書きリスト（*）**: 特徴、判断基準、並列の選択肢など、順序に依存しない列挙に使用する。無用なナンバリングを行わない。
- **例外の許容**:
  - 本原則は絶対的な縛りではなく「普遍的な基本方針」である。
  - 意図を持った明確な理由（例：フレームワークとして4つ必要な「4つのモノサシ」、2者択一の分岐、必要不可欠なFAQ数など）がある場合は崩してよい。ただし、**無自覚・成り行きで3要素以外にしてはならない**。

### 同一階層における論理構造の整合と語彙統一 (Logical Alignment & Vocabulary)

同一階層に並ぶ要素は、思いつきで並べるのではなく、必ず整合性のある論理フレームワークを採用して整理する。

- **論理フレームワークの適用**:
  - **MECE（漏れなくダブりなく）**: 重複や抜けのない網羅的な分類・切り口。
  - **時系列・プロセス順**: 準備（選定） → 実行（調達） → 手放し（出口） → 維持（基盤）
  - **PREP法**: Point（結論） → Reason（理由） → Example（具体例） → Point（再結論）
  - **Why / What / How**: なぜ重要か（背景・理由） → 何をするか（本質・概念） → どうやるか（具体策・手順）
  - **全体 ⇔ 部分（演繹・帰納）**: 全体像から要素への分解、または具体的事象からの構造化
- **語彙の完全統一と階層接続**:
  - 記事全体で使用する主要概念やフレームワーク（例: 「3つの基本アプローチ」「5つのLevel」）の呼称・表記を全編で完全統一する（「レベル/Level」「ステップ/Level」等の混同・表記揺れを排除）。
  - 導入部において、上位の基本方針・アプローチと、下位の実践レベル・ステップがどのような関係にあるのかを読者に迷いなくスムーズに接続する。

## 🛠️ 実践プラクティス (Practical Standards)

### 構造の事実で語る（カウント明記の抑制）

- **原則**: 見出しや本文で「3つの型」「3つのコツ」「3つの視点」「3つの柱」などと数字を連呼しない。
- **実践方針**:
  - 項目が3つ並んでいるという「構造的な事実」だけで、美しさとリズム、説得力は十分に伝わる。
  - 見出しには「選び方」「コツ」「方法」「注意点」など自然で洗練された言葉を用いる。
  - **例外**: 記事全体の導入や核となるフレームワーク（例：「4つのモノサシ」）など、読者のリード（道しるべ）として数を明示した方が理解しやすい場合に限り、ここぞという場面で数を明記する。

### 読者主体のトーン＆マナー（意思決定への寄り添い）

- **原則**: 評価やアドバイスは外部からの「上から目線の判定」ではなく、「読者自身の納得感・意思決定」に寄り添うトーンにする。
- **改善例**:
  - ❌ `総合判定：購入を強く推奨。` （外部からの押し付けに見える）
  - ⭕ `判定結果のめやす：自分にとって「買い」の判断。` （読者自身の意思決定を支援する）
- **断定表現の配慮**:
  - ショートカットキーやトラブルシューティング等の環境依存の挙動において、「有効になります」等の過度な断定を避け、「改善することがあります」等の配慮ある表現とする。
- **公式ツール・高度機能の紹介マナー**:
  - 関連する公式便利ツール（Windows PowerToys FancyZones等）は、本文中で価値や利便性をスマートに1文で触れ、詳細な初期設定手順や応用レシピはコメントアウトや別記事展開として切り分ける（主軸を脱線させず、読者の知的好奇心を満たす）。

### 言葉の平易さと自然さ（ジャーゴン・不自然な比喩・不要装飾の排除）

- **原則**: 専門用語・心理学用語・過度なカタカナ語・独自の造語は、強い意志や必然性がない限り日常語へ開く。
- **改善例**:
  - ❌ `ウィルパワーを消耗する` → ⭕ `決断のエネルギーを使う` / `考えるエネルギーをすり減らす`
  - ❌ `ハシゴ・延命検索をやめる` → ⭕ `最安値探しの深追いをやめる`
- **不自然な身体的比喩の排除**:
  - ❌ `人間が汗をかかずに済む` / `一切汗をかかない` 等の違和感を与える比喩を避け、簡潔で実用的な表現を用いる。
- **不要な装飾語・誇大表現の排除**:
  - 「黄金の〜」「神〜」「〜という無駄」などの重複・安易な装飾語・過度な煽り文句を排除し、信頼性の高い落ち着いたトーンを維持する。
- **野暮なメタ説明の排除**:
  - 「表を見ればわかること」（例: 「〜を5段階のバーで視覚化しています」）を文章で野暮に説明しない。
- **例外規定**:
  - 記事内で象徴的な独自キーワード・コンセプトとして意図的に提示したい場合は、安易に本文へ混ぜず、**読者にとっての価値や定義を熟考・相談した上で採用判断**する。

### Webブログにおけるプレーン表記と視覚化（アクセシビリティ・可読性）

- **プレーン表記の徹底（TeX数式の排除）**:
  - Web・ブログ記事において、KaTeX等のTeX数式表記（`$$...$$`）は原則使用しない。スマホ閲覧時の可読性、WordPress入稿時の互換性、一般読者にとっての親しみやすさを最優先する。
  - プレーンな太字テキスト、コードブロック、またはテーマの強調ボックス（計算ボックス）を用いて直感的に表現する。
  - ⭕ `実質価格 ＝ 支払い総額 − ポイント還元 − リセールバリュー（売却想定額）`
- **Markdownテーブルの視覚化ルール**:
  - 評価マトリクス等の視覚化記号は、フォントレンダリング差で幅ズレが生じる記号（■/□ 等）を避け、安定した等幅記号（★☆ 等）を採用する。
  - 記事全体のマップ・要約テーブル内のタイトル項目は、後述の該当見出し名（コロン以降）と1字の狂いもなく完全一致させる。

### 滑らかな文脈接続（接続詞と展開の精査）

- **原則**: 「なお、」「しかし、」などの接続詞で文脈が途切れたり唐突に飛んだりしないよう、段落間の論理的な繋がりを丁寧に推敲する。
- 前の段落で述べた内容を受けて自然に次へ展開するブリッジ文章を入れる。

## 📋 執筆・推敲時のセルフチェックリスト

記事の構成案作成時および推敲時には、必ず以下の問いに立ち返って確認する。

- [ ] **階層と3部品**: 中間〜下位のアウトライン階層（H3/H4/箇条書き）は可能な限り3部品で構成されているか？（3部品以外の場合、明確な意図があるか？）
- [ ] **リスト記法の厳密さ**: 順序関係のある手順のみナンバリング（1. 2. 3.）にし、並列列挙は箇条書き（*）にできているか？（不要なStepラベルを付けていないか？）
- [ ] **同一階層の論理と語彙**: 同じ階層に並ぶ要素は適切な論理構造を持ち、主要概念の語彙や表記が全編で統一され、スムーズに接続されているか？
- [ ] **カウントの抑制**: 見出しや本文で数字（「3つの〜」等）を連呼せず、構造の事実で語れているか？
- [ ] **読者主体のトーン**: 読者自身の納得感や意思決定に寄り添うトーンか？環境依存の挙動に配慮ある表現（断定の緩和）ができているか？
- [ ] **公式ツールの紹介マナー**: 関連公式ツール（FancyZones等）は本文1文での価値提示にとどめ、詳細設定は別記事やコメントアウト等に切り分ける配慮ができているか？
- [ ] **言葉の平易さと比喩・装飾の排除**: ウィルパワー等の造語・ジャーゴンを使わず、不自然な身体的比喩（「汗をかく」等）や不要な装飾語（「黄金の〜」等）、野暮なメタ説明が排除されているか？
- [ ] **プレーン表記とテーブルの端正さ**: TeX等の過剰な記法を使わず、マトリクス記号は等幅（★☆等）で崩れず、表内タイトルは後述見出しと完全一致しているか？
- [ ] **接続の滑らかさ**: 段落の繋がりや接続詞に不自然な引っかかりがないか？
