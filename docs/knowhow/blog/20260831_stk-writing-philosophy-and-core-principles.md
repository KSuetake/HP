## 💡 コアフィロソフィー (Core Philosophy)

本ドキュメントは、一般的なWebノウハウの上位に位置づけられる、**STK Labにおける最上級の執筆規範・思考フレームワーク**である。
AIおよび執筆者は、記事の企画・構成・執筆・推敲・レビューの全フェーズにおいて、常に本規範を最優先で適用する。

単に情報を並べるのではなく、**「読者が迷わず、心地よく理解でき、生活にゆとりを取り戻せるか」**を究極の目的として文章を紡ぐ。

## 🏛️ 普遍的原則 (Universal Principles)

### 1. 階層構造と「3部品構成」の原則 (The Rule of Three Components)

- **原則**: アウトラインは論理的な階層構造（H2 → H3 → 箇条書き/H4）で組み立て、**各階層は可能な限り「3つの部品（3要素）」で構成する**。
- **意図と効能**:
  - 人間の脳が最も記憶・処理しやすく、安心感とリズムを覚える黄金数が「3」。
  - 2要素だと比較や対立に偏りやすく、4要素以上だと情報過多で流し読みしにくくなる。3要素に整理することで論点の本質が凝縮される。
- **階層ごとの適用例**:
  - H2（メイン章）: 導入 → 基礎（判断基準） → 実践ステップ → FAQ → まとめ
  - H3（実践の各節）: ①選定（何を買うか） / ②調達・タイミング（いつ買うか） / ③出口（どう手放すか）
  - H4 / 箇条書き: 各節の中身も3つの具体例や3つのステップで整理する。
- **例外の許容**:
  - 本原則は絶対的な縛りではなく「普遍的な基本方針」である。
  - 意図を持った明確な理由（例：フレームワークとして4つ必要な「4つのモノサシ」、2者択一の分岐、必要不可欠なFAQ数など）がある場合は崩してよい。ただし、**無自覚・成り行きで3要素以外にしてはならない**。

### 2. 同一階層における論理構造の整合（ロジカル・ビジネスライティング）

同一階層に並ぶ要素は、思いつきで並べるのではなく、必ず整合性のある論理フレームワークを採用して整理する。

- **MECE（漏れなくダブりなく）**: 重複や抜けのない網羅的な分類。
- **プロセス・時系列順**: 準備（選定） → 実行（調達） → 手放し（出口） → 維持（基盤）
- **PREP法**: Point（結論） → Reason（理由） → Example（具体例） → Point（再結論）
- **Why / What / How**: なぜ重要か（背景） → 何をするか（概念） → どうやるか（具体策）
- **Must / Want**: 必須条件と希望条件の明確な切り分け

## 🛠️ 具体的な執筆・推敲プラクティス (Practical Standards)

### 1. カウント明記の抑制（構造の事実で語る）

- **原則**: 見出しや本文で「3つの型」「3つのコツ」「3つの視点」「3つの柱」などと数字を連呼しない。
- **実践方針**:
  - 項目が3つ並んでいるという「構造的な事実」だけで、美しさとリズム、説得力は十分に伝わる。
  - 見出しには「選び方」「コツ」「方法」「注意点」など自然で洗練された言葉を用いる。
  - **例外**: 記事全体の導入や核となるフレームワーク（例：「4つのモノサシ」）など、読者のリード（道しるべ）として数を明示した方が理解しやすい場合に限り、ここぞという場面で数を明記する。

### 2. 読者主体のトーン＆マナー（意思決定への寄り添い）

- **原則**: 評価やアドバイスは外部からの「上から目線の判定」ではなく、「読者自身の納得感・意思決定」に寄り添うトーンにする。
- **改善例**:
  - ❌ `総合判定：購入を強く推奨。` （外部からの押し付けに見える）
  - ⭕ `判定結果のめやす：自分にとって「買い」の判断。` （読者自身の意思決定を支援する）
- 読者に寄り添い、押し付けず、読者が自発的に生活を整えたくなる表現を選ぶ。

### 3. 造語・ジャーゴンの排除と慎重な採用判断

- **原則**: 専門用語・心理学用語・過度なカタカナ語・独自の造語は、強い意志や必然性がない限り日常語へ開く。
- **改善例**:
  - ❌ `ウィルパワーを消耗する` → ⭕ `決断のエネルギーを使う` / `考えるエネルギーをすり減らす`
  - ❌ `ハシゴ・延命検索をやめる` → ⭕ `最安値探しの深追いをやめる`
- **例外規定**:
  - 記事内で象徴的な独自キーワード・コンセプトとして意図的に提示したい場合は、安易に本文へ混ぜず、**読者にとっての価値や定義を熟考・相談した上で採用判断**する。

### 4. Webブログにおけるプレーン表記（TeXの排除）

- **原則**: Web・ブログ記事において、KaTeX等のTeX数式表記（`$$...$$`）は原則使用しない。
- **理由**: スマホ閲覧時の可読性、WordPress（Gutenberg）入稿時の互換性、一般読者にとっての親しみやすさを最優先する。
- **実践方針**:
  - プレーンな太字テキスト、コードブロック、またはテーマの強調ボックス（計算ボックス）を用いて直感的に表現する。
  - ⭕ `実質価格 ＝ 支払い総額 − ポイント還元 − リセールバリュー（売却想定額）`

### 5. 滑らかな文脈接続（接続詞の精査）

- **原則**: 「なお、」「しかし、」などの接続詞で文脈が途切れたり唐突に飛んだりしないよう、段落間の論理的な繋がりを丁寧に推敲する。

## 📋 執筆・推敲時の最上位セルフチェックリスト

記事の構成案作成時および推敲時には、必ず以下の問いに立ち返って確認する。

- [ ] **階層と3部品**: アウトラインの各階層は可能な限り3部品で構成されているか？（3部品以外の場合、明確な意図があるか？）
- [ ] **同一階層の論理**: 同じ階層に並ぶ要素は、MECEやプロセス順など適切な論理構造を持っているか？
- [ ] **カウントの抑制**: 見出しで「3つの〜」を連呼していないか？（構造の事実で語れているか？）
- [ ] **言葉の平易さ**: ウィルパワーや造語などのジャーゴンを使わず、中学生でもスッと伝わる言葉になっているか？
- [ ] **プレーンな記法**: TeXなどの過剰な記法を使わず、プレーンテキストやテーマ装飾で分かりやすく表現できているか？
- [ ] **読者主体の目線**: 読者自身の納得感や「買いの判断」を促す寄り添ったトーンになっているか？
- [ ] **接続の滑らかさ**: 段落の繋がりや接続詞に不自然な引っかかりがないか？
