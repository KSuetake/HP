# Webノウハウ抽出スキル (web-knowhow-extractor)

Web記事から幅広いジャンル（IT開発、ビジネス、デザイン、マーケティング、生産性、思考法など）のノウハウ、要点、具体例を適当な粒度で整理し、今後再利用できるようにドキュメント化します。

## 概要と保存ルール

- **保存ディレクトリ**: `docs/knowhow/<category>/`
  - `<category>` はジャンルに応じて柔軟に設定します。
  - カテゴリ例: `dev`, `business`, `design`, `marketing`, `productivity`, `management`, `general` など
- **ファイル命名規則**: `YYYYMMDD_<kebab-case-topic>.md`
  - 例: `docs/knowhow/business/20260730_product-positioning-framework.md`
  - 例: `docs/knowhow/dev/20260730_react-state-management.md`
  - 日付、カテゴリ、直感的なトピック名で構成し、ディレクトリ一覧を見るだけで識別できるようにします。

## 実行フロー

1. **コンテンツの取得**:
   - ユーザー提供のURL、または自発的に検索・発見したURLに対し、`read_url_content` 等を用いて記事本文を取得します。
2. **ノウハウの抽出と適当な粒度での整理**:
   - 記事のジャンル（技術、ビジネスモデル、デザインのベストプラクティス、ノウハウ等）に応じ、コアとなる「要点」「具体例」「実践手順」「注意点・リスク」を中心に抽出します。
3. **ドキュメントの作成**:
   - 以下の「汎用ノウハウテンプレート」に基づき、`docs/knowhow/<category>/YYYYMMDD_<kebab-case-topic>.md` に書き出します。
   - 記事の性質に合わせてセクションの追加・調整を臨機応変に行って構いません。

## ポイント・ガイドライン
- **参照元の記載**: URL単体ではなく、必ず **元記事のタイトルとURLをセットで併記**（例: `- **参照記事**: [元記事タイトル](URL)`）してください。複数記事を統合した場合は、各元記事のタイトルとURLをリスト形式で列挙します。
- **幅広いジャンルへの対応**: 開発技術に限らず、マーケティング論、プロダクト管理、デザイン原則、業務効率化など、多様な分野のノウハウに適用してください。
- **臨機応変なテンプレ調整**: コードが含まれない一般的なノウハウ記事の場合、コードブロックをチェックリストやステップ解説に変更するなど、記事の形式に合わせて柔軟に構成を調整してください。
- **同カテゴリ内ノウハウへの安易なリンク禁止**: ディレクトリ構成を見れば一覧判断できる同一カテゴリ・同ディレクトリ内の別ファイルを、理由なく「関連ドキュメント」として箇条書き・リンクしないでください。「補足・関連情報」には、外部ツール・推薦図書・Q&Aなど、そこに記載すべき明確な理由や付加価値がある情報のみを記述してください。
- **パス・秘匿情報の扱い**: ドキュメント内のファイル参照などはリポジトリルートからの相対パスを使用し、ユーザー環境等の秘匿情報はプレースホルダー（例: `<username>`, `<project_root>`）に置き換えてください。
- **明確な命名**: ファイル名は英数字とハイフン (`-`) の kebab-case で記述し、一目で中身が推測できる明確な名称をつけてください。
