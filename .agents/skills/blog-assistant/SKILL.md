# ブログ制作・メンテナンス総合支援スキル (blog-assistant)

ブログの企画、構成作成、本文執筆、校正、公開前チェック、リライト、およびWordPress（Cocoonテーマ等）への入稿を見越したデザイン・画像指定などの作業において、`docs/knowhow/` 配下のナレッジベースから関連度が高く重要なノウハウを自律的に検索・取捨選択して適用します。

## ノウハウの検索と適用

タスク受信時、`docs/knowhow/` から関連するキーワードやトピックでドキュメントを検索し、要点やチェックリストを自律的に選択して作業に反映します。

> [!IMPORTANT]
> ### 🏛️ STK Lab 最上位ライティング規範 & 記事管理プロセスの適用
> - `docs/knowhow/blog/*_stk-writing-philosophy-and-core-principles.md`（STK Lab 最上位ライティング規範）は、一般的なWebノウハウの上位に位置づけられる最重要ルールです。企画・構成案作成・本文執筆・推敲・レビューの全フェーズにおいて、常に最優先で適用してください。
> - 記事のディレクトリ構造、設計書と記事の一体管理、制作プロセスについては `articles/README.md` に厳格に従ってください。

## 対応ユースケース

ユーザーのニーズや入力状態に合わせて以下の作業に対応します。

- **企画・キーワード選定**: 0ベースのテーマ検討、ロングテールキーワードの選定、ターゲット読者や検索意図の整理
- **記事設計書の策定 (`design.md`)**: 主題、ペルソナ、トンマナ、3部品構成に基づく詳細アウトラインの設計
- **本文執筆・ドラフト作成 (`article.md`)**: リード文の執筆、本文の執筆・整形、表やチェックリスト等の装飾（無理な図式化を避け、適切な表現手段を選択）
- **WordPress入稿前提の表現・画像指示**: 
  - アイキャッチ画像および本文中の挿入画像案（画像イメージ、生成プロンプト、Altテキスト、設置位置）のコメント指定
  - WordPress（Cocoon等）の装飾・ブロック指定（吹き出し、案内ボックス、評価星、アフィリエイトボタン・ブログカード化等）の埋め込み
- **独立サブエージェント二重監査**: アウトライン整合性監査役およびファクトチェック監査役による厳格な自動検証
- **WordPressドラフト登録支援**:
  - REST API / MCP / 登録スクリプト（`scripts/wp-draft-post.js`）を用いた安全な下書き登録（※`docs/wordpress-mcp-operations.md` 準拠）
- **レビュー・推敲・校正**: 可読性向上、誤字脱字・表記揺れの修正、論理展開の調整
- **公開前チェック**: 事前チェックリストに基づくメタ要素・見出し・リンク・表示確認
- **リライト・記事メンテナンス**: 公開済み記事の課題分析、最新情報の反映、構成再構築（設計書と本文の一体更新）

## WordPress入稿・ドラフト運用ルール

ローカル（Markdown）で記事を検討・執筆する際は、将来的にWordPressへスムーズに移行・編集できるよう以下のコメント形式で指示を埋め込みます。
また、WordPress への入稿・登録を行う際は、必ず [`docs/wordpress-mcp-operations.md`](docs/wordpress-mcp-operations.md) に定義された運用ガイドラインおよび安全ガードレールに従います。

1. **設計書と記事本文の一体管理 (`design.md` & `article.md`)**
   - 記事を新設・更新する際は、必ず記事ごとのディレクトリに `design.md`（設計書）と `article.md`（本文）をセットで維持・更新する。
2. **表現手段の適切な選択（脱・無理な図式化）**
   - なんでも無理やりASCIIアート等で図式化せず、キー操作や比較データなどはMarkdownテーブル表記や整理された箇条書きなど、情報に最も適した表現手段を選択する。
3. **画像挿入指示 (`<!-- 🖼️ [画像指定] -->`)**
   - アイキャッチ画像および各章の理解を助ける図解・イメージ画像の挿入指示を入れる。
   - 内容：画像のテーマ・構図、生成プロンプト（AI生成用）、Altテキスト、推奨設置位置。
4. **WordPressブロック・装飾指示 (`<!-- 💡 [WordPress表現指示] -->`)**
   - テーマ（Cocoon等）特有の装飾・CSS・ブロックプラグインへの変換指示を入れる。
   - 例：吹き出し（キャラクター/対話形式）、Cocoon見出しボックス、バッジ・ボタン、ブログカード化、評価（星）、アフィリエイトリンクのバナー/ボタン化など。
5. **自然なWin-Win導線（紹介・アフィリエイト枠）の配慮**
   - 登録や課金が必要な実践ノウハウにおいても、読者が自発的に試したくなる「お得な入り口（公式無料トライアルや特典など）」を自然な文脈で提供する。
   - 読者にとっての価値と執筆者への還元（紹介料・アフィリエイト等）が両立するWin-Win構図を意識する。
   - ただし、過度なセールス感や押し付けを徹底的に排除し、読者に辟易されない節度ある配置（WordPressブロック指示コメントによる枠設定）とする。
6. **【絶対遵守】ドラフト強制ルール（Draft-Only）**
   - API / MCP / CLI スクリプトを経由した登録は、**常に `status: draft`（下書き）のみ**を許可する。
   - AI アシスタントが自律的に即時公開（`publish`）を行うことは固く禁ずる。
   - 最終公開は必ず WordPress 管理画面上で目視プレビュー（Cocoon装飾、アイキャッチ、スマホ表示崩れ等）を確認後、人間が手動で実施する。

## 進行手順（標準7フェーズ）

1. **状況の確認**: 必要に応じてターゲット、キーワード、目的、作業範囲を確認します。
2. **記事設計書の起草 (`design.md`)**: 主題、ペルソナ、3部品構成アウトラインを設計書としてまとめます。
3. **【合意ゲート】詳細アウトライン・3部品構成の提示と合意**:
   - 本文執筆に入る前に、設計書のアウトラインとトーン＆マナーをユーザーへ提示し、承認を得てから本文執筆に進みます。
4. **本文執筆 (`article.md`)**: 承認された設計書に基づき、適切な表現形式（表・箇条書き・指示コメント）で執筆します。
5. **【必須・独立サブエージェント二重監査】**:
   - 本文執筆後、ユーザーへレビュー依頼を出す前に、**2体の独立した監査役サブエージェント**を起動して監査を実施します。
     - **監査役1（アウトライン整合性）**: 事前合意アウトライン・設計書と本文の間に齟齬・脱落・意図せぬ変更がないかを監査。
     - **監査役2（ファクトチェック・技術仕様）**: 公式仕様（無料/有料の違い、ショートカット、数値等）に誤りがないかを監査。
   - 監査役から指摘が出た場合は本文／設計書を修正し、両監査役が「合格 (PASS)」を出すまで反復します。
6. **ユーザーレビュー依頼とマージ**: 二重監査を完全にパスした成果物のみを提示し、ユーザーレビューを仰ぎます。明示的な許可・指示を得てからPRマージを実行します。
7. **ドラフト下書き登録とプレビュー確認**:
   - 本文および画像アセットの準備完了後、`scripts/wp-draft-post.js` または MCP を利用して安全に下書き（`status: draft`）として登録します。
   - ユーザーへ管理画面でのプレビュー確認を依頼し、最終的な公開（Publish）は手動で行います。
