# STK Lab 記事管理・作成プロセスガイドライン (`articles/README.md`)

本ドキュメントは、STK Labにおける記事ディレクトリの構成基準、設計書（`design.md`）と記事本文（`article.md`）の一体管理原則、およびAIエージェント・執筆者が従うべき標準制作・監査プロセスを定義する運用指針である。

---

## 1. 記事ディレクトリ構成の標準仕様

各記事は `articles/` 配下に独立したスラッグ名のディレクトリを持ち、以下の3つの要素で構成する。

```
articles/
└── <記事スラッグ>/
    ├── article.md        # 記事本文（Markdown、WordPress入稿用コメント指示付き）
    ├── design.md         # 記事設計書（主題、ペルソナ、トンマナ、アウトライン等）
    └── images/           # 記事固有の画像アセット（アイキャッチ、図解等）
        └── .gitkeep
```

### ファイルの役割
- **`article.md` (記事本文)**:
  - 読者に届ける記事の実体。
  - WordPress（Cocoon等）への入稿を前提とした画像指示（`<!-- 🖼️ [画像指定] -->`）や装飾指示（`<!-- 💡 [WordPress表現指示] -->`）を含む。
- **`design.md` (記事設計書)**:
  - 記事の設計図。主題・目的、対象読者（ペルソナ）、トーン＆マナー、前提条件、章立て・詳細アウトライン（3部品構成）、アフィリエイト/紹介導線設計を記録する。
- **`images/` (画像アセット)**:
  - 本文に挿入するアイキャッチ画像、図解画像、インフォグラフィック等の元データを管理する。

---

## 2. 設計書と記事の一体更新原則 (Documentation Integrity)

- **不可分の一体運用**:
  - 記事本文と設計書は「双子のドキュメント」として扱う。新規作成時は必ず両方を発行する。
  - 記事の加筆・修正・リライトを行う際は、必ず `design.md` のアウトラインや前提もセットで更新する。
- **乖離の禁止**:
  - 本文だけを修正して設計書を放置すること、または設計書と本文の論理構造・見出し階層が矛盾した状態のまま放置することを固く禁ずる。

---

## 3. 記事制作・更新の標準プロセス（7フェーズ）

AIエージェントおよび執筆者は、以下の工程リストに従って作業を進める。

```
Phase 1: 企画・要件確認（Issueや要望の理解）
   ▼
Phase 2: 記事設計書の策定（design.md の起草）
   ▼
Phase 3: 【合意ゲート】アウトライン・トンマナの提示とユーザー合意
   ▼
Phase 4: 本文執筆（article.md の作成・適切な表現手段の選択）
   ▼
Phase 5: 【独立サブエージェント二重監査】（アウトライン整合性 ＆ ファクトチェック）
   ▼
Phase 6: ユーザーレビュー依頼（監査をパスした成果物のみを提示）
   ▼
Phase 7: ユーザー承認に基づくPRマージ・クリーンアップ
```

### Phase 1: 企画・要件確認
- Issueやユーザー要望から、記事のテーマ、解決すべき課題、キーワードを明確化する。

### Phase 2: 記事設計書の策定 (`design.md`)
- `articles/<記事スラッグ>/design.md` を作成する。
- `docs/knowhow/blog/20260831_stk-writing-philosophy-and-core-principles.md`（STK Lab最上位ライティング規範）を適用し、中位〜下位構造を「3部品構成」で整理した詳細アウトラインを組む。

### Phase 3: 【合意ゲート】アウトライン・トンマナの提示と合意
- 本文執筆に入る前に、詳細アウトラインとトンマナを必ずユーザーに提示し、合意・承認を得る。
- ユーザーからのフィードバックがある場合は、設計書を更新して合意を取り直す。

### Phase 4: 本文執筆 (`article.md`)
- 承認された設計書に基づき本文を執筆する。
- **表現手段の適切な選択（脱・無理な図式化）**:
  - 何でもかんでもASCIIアート等の図式に頼らず、表（Markdownテーブル）や箇条書きなど、情報に応じた最適な表現を選択する。
- **単一正本（最上位ライティング規範）の遵守**:
  - 本文執筆にあたっては、単一正本（Single Source of Truth: SSOT）である **[最上位ライティング規範 (`docs/knowhow/blog/20260831_stk-writing-philosophy-and-core-principles.md`)](../docs/knowhow/blog/20260831_stk-writing-philosophy-and-core-principles.md)**（普遍的原則、実践プラクティス、およびセルフチェックリスト）を厳格に適用する。
- **WordPress表現・画像指示の埋め込み**:
  - アイキャッチや図解の生成プロンプト、吹き出し、案内ボックス、キーボードキー装飾等を明記する。

### Phase 5: 【独立サブエージェント二重監査】
本文執筆完了後、直ちにユーザーへレビュー依頼を出してはならない。**それぞれ独立した役割を持つ2体の監査役サブエージェント**に監査を実施させ、品質を担保する。

1. **アウトライン・設計整合性監査役**:
   - 事前に合意した `design.md` のアウトラインと `article.md` の本文に齟齬・抜け漏れ・意図せぬ変更がないかを厳格に監査する。
2. **ファクトチェック・技術仕様監査役**:
   - 記事内で紹介されている機能、公式仕様（無料/有料の違い、ショートカットキー、AIツールの動作等）、数値、手順に誤りや古い情報がないかを客観的に監査する。
3. **反復修正**:
   - 監査役から指摘事項（Issue/Warning）が出た場合、本文または設計書を修正し、両監査役から「PASS（合格）」が出るまで反復する。

### Phase 6: ユーザーレビュー依頼
- 二重監査を完全にパスした成果物のみをユーザーへ提示し、最終レビューを仰ぐ。
- 監査の実施結果およびパスした旨をレビュー依頼時に明記する。

### Phase 7: ユーザー承認に基づくPRマージ
- ユーザーからの明示的な承認・指示を得た後にのみ、PRのマージおよび作業ブランチのクリーンアップを実行する（無断マージの厳禁）。

## 4. 関連ドキュメント・最上位規範（単一正本）

本ガイドラインを実践するにあたり、以下のドキュメントを参照・遵守すること。

- **[最上位ライティング規範 (`docs/knowhow/blog/20260831_stk-writing-philosophy-and-core-principles.md`)](../docs/knowhow/blog/20260831_stk-writing-philosophy-and-core-principles.md)** 【単一正本 (SSOT)】:
  - STK Labにおける記事執筆・エディトリアル規約の**唯一の正本**。読者への伴走思想、普遍的原則（3部品構成、論理整合・語彙統一）、実践プラクティス（構造で語る、読者主体、平易な言葉、プレーン表記・視覚化、文脈接続）、および推敲セルフチェックリストをすべてここに集約・管理する。
- **[ブログ制作支援スキル (`.agents/skills/blog-assistant/SKILL.md`)](../.agents/skills/blog-assistant/SKILL.md)**:
  - AIエージェントが自律的に実行する作業標準手順、WordPressドラフト運用ルール（下書き限定、即時公開禁止、正本規範の参照義務）。
